## Decisiones tecnicas
- **Paths absolutos en spec via SPECPATH**: PyInstaller resuelve paths del .spec relativos al
  directorio del spec, no al CWD. Por eso `src/main.py` en `build/pyinstaller.spec` se busca
  en `build/src/main.py`. Solucion: calcular `ROOT = os.path.abspath(os.path.join(SPECPATH, '..'))`
  y derivar todos los paths desde ahi.
- **Permiso a nivel de job, no workflow**: `permissions: contents: write` se agrego al `job`
  build-windows en lugar del nivel root del workflow para minimizar superficie.
- **Recrear tag en lugar de force-push**: el tag v3.1.0 inicial apuntaba a un commit sin el fix
  de permisos. Se borro localmente y en remoto, y se recreo apuntando al commit nuevo.
  Mas limpio que `git tag -f` + `git push --force`.

## Descubrimientos
- `softprops/action-gh-release@v2` necesita `contents: write` para crear releases. Sin eso
  falla con "Resource not accessible by integration" — error confuso, no menciona permisos.
- GitHub artifacts vienen siempre envueltos en .zip, aunque el contenido sea un solo .exe.
  El installer/portable de la release SI vienen como .exe directo.
- El usuario hizo un commit posterior `088919d` (fix deps Python 3.14) directamente en GitHub.
  El build de ese commit tambien paso OK con Python 3.11 del workflow.
