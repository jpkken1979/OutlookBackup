DATA FLOW: Normal Sync Operation
═════════════════════════════════

1. Frontend (PWA)
   ↓ HTTP POST with {"session_id", "responses"}

2. Gateway Handler (to implement)
   ↓ Validate inputs
   ↓ Call sync.async_sync_responses()

3. ShuPWASync.async_sync_responses()
   ↓ Validate session_id exists
   ↓ Fetch existing responses from DB
   ↓ Merge new responses (new values override)
   ↓ Update status → "submitted"
   ↓ Set synced_at timestamp
   ↓ Log operation at INFO level
   ↓ Return {"status": "success", "synced_to_goal": "..."}

4. Gateway Handler
   ↓ Return HTTP 200 + JSON response

5. Frontend
   ↓ Clear IndexedDB draft
   ↓ Mark as synced


SESSION LIFECYCLE
═════════════════

    Creation (draft)
         ↓
    [--- Offline Period (no sync) ---]
         ↓
    Sync Attempt
         ├─ Success ────→ submitted
         │                  ↓
         │            synced_at set
         │                  ↓
         │            (can delete)
         │
         └─ Failure ───→ remains draft
                            ↓
                    (retry later)


SINGLETON PATTERN
═════════════════

    get_pwa_sync() ────┐
                       ├─→ First call: create instance
                       │   store in _sync_instance
                       │
    get_pwa_sync() ────┤
    (2nd call)         ├─→ Return existing instance
                       │
    get_pwa_sync() ────┘

    Result: Single database connection, thread-safe instance

  • React 19 + TypeScript
  • Service Worker (offline)
  • IndexedDB (local queue)
  • Fetch API (sync)

Backend:
  • Python 3.10+

  • pathlib (path handling)

Testing:
  • pytest (framework)
  • pytest-asyncio (async tests)
  • pytest-cov (coverage)


PERFORMANCE NOTES
═════════════════

Database:
  • Suitable for <10k sessions
  • Indices on status, goal_id for fast filtering
  • Consider PostgreSQL for >100k sessions

Memory:
  • Singleton pattern prevents duplicate connections
  • Lazy loading of database module

Concurrency:
  • SQLite with default timeout handling
  • Enable WAL mode for concurrent reads
  • Serialize writes for safety


SECURITY CONSIDERATIONS
═══════════════════════

Current Implementation:
  • No encryption at rest (SQLite plain text)
  • No authentication on service
  • No input sanitization (relies on gateway)

Future Enhancements:
  • Encrypt responses column
  • Add HMAC-SHA256 integrity check
  • Rate limiting at gateway level
  • Audit log of all sync operations
