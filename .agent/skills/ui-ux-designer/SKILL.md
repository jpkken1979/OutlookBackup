## 🎯 Workflow UX Práctico (Proceso Completo)

### Fase 1: Discovery (1-2 semanas)
```
1. Kickoff y definición de éxito
   → ¿Qué métricas mejoran si el diseño funciona?
   → Jobs To Be Done: "Cuando [situación], quiero [motivación], para [resultado]"

2. Investigación
   → Entrevistas usuarios: 5 son suficientes para patrones (Nielsen)
   → Análisis competitivo: 3-5 productos similares
   → Heurísticas existentes: recorrer el producto con 10 heurísticas de Nielsen

3. Síntesis
   → Affinity diagram (FigJam)
   → Personas (máximo 3, basadas en datos reales)
   → User Journey Map (estado actual)
```

### Fase 2: Define (3-5 días)
```
4. Problem Statement
   → "[Persona] necesita [necesidad] porque [insight]"
   → How Might We: "¿Cómo podríamos...?"

5. Priorización
   → Impact vs Effort matrix
   → MoSCoW: Must/Should/Could/Won't
```

### Fase 3: Design (2-4 semanas)
```
6. Flujos de usuario (user flows)
   → Cada pantalla como nodo, decisiones como rombos
   → Cubrir: flujo feliz + errores + edge cases

7. Wireframes de baja fidelidad
   → Lápiz/FigJam: rapidez > perfección
   → Validar estructura antes de color/tipografía

8. Diseño de alta fidelidad en Figma
   → Tokens primero (color, spacing, typography)
   → Atomic Design: átomos → moléculas → organismos
   → Auto Layout en todos los componentes
   → Dark Mode con Variables multi-mode

9. Prototipo interactivo
   → Smart Animate para micro-interacciones
   → Cubrir todos los estados: Default, Hover, Loading, Error, Empty, Success
```

### Fase 4: Validate (3-5 días)
```
10. Usability testing (5 usuarios)
    → Tareas específicas, no preguntas de opinión
    → Observar, no guiar
    → Métricas: completion rate, time-on-task, errores

11. Iteración basada en findings
    → Priorizar por severidad (crítico/mayor/menor)
```

### Fase 5: Handoff (2-3 días)
```
12. Preparar para desarrollo
    → Dev Mode en Figma activo
    → Variables vinculadas a todos los valores
    → Anotaciones de comportamiento (no solo visual)
    → Especificar: animaciones (easing, duración), gestos, responsividad

13. Design QA
    → Revisar implementación vs diseño lado a lado
    → Lista de discrepancias categorizadas por severidad
```

## 🎨 Decisiones de Diseño Visual — Framework Rápido

### Elección de colores
```
Primary   → Acción principal del producto (CTA, links activos)
Secondary → Acciones secundarias, highlights
Neutral   → Texto, fondos, bordes
Semantic  → Éxito(verde), Error(rojo), Warning(amarillo), Info(azul)

Regla 60-30-10:
60% → Color dominante (fondo, base)
30% → Color secundario (áreas de soporte)
10% → Acento (CTAs, elementos críticos)
```

### Elección de tipografía
```
Siempre: máximo 2 familias (display + body)

Display: personalidad de la marca
  → Geometric sans (moderno, tecnológico): Space Grotesk, DM Sans, Outfit
  → Humanist sans (cálido, accesible): Plus Jakarta, Nunito, Figtree  
  → Serif (elegante, editorial): Playfair Display, Cormorant, Fraunces

Body: legibilidad pura
  → Inter, IBM Plex Sans, Source Sans 3 (todas excelentes a 14-16px)

Escala modular (ratio 1.25 - Major Third):
  12 → 15 → 19 → 24 → 30 → 38 → 48 → 60px
```

### Espaciado consistente (base-8)
```
Base unit: 4px (half-unit) ó 8px (full unit)

Escala:  4 | 8 | 12 | 16 | 24 | 32 | 48 | 64 | 96 | 128px
Tailwind: 1 | 2 |  3 |  4 |  6 |  8 | 12 | 16 | 24 |  32

Regla: NUNCA valores arbitrarios (no 13px, no 37px)
```

### Contrastes WCAG
```
Texto normal (< 18pt):  ratio ≥ 4.5:1  (AA)  /  ≥ 7:1  (AAA)
Texto grande (≥ 18pt):  ratio ≥ 3:1   (AA)  /  ≥ 4.5:1 (AAA)
UI components / icons:  ratio ≥ 3:1   (AA)

Herramientas: Figma plugin "Contrast", webaim.org/contrast-checker
```

## 🔲 Estados que SIEMPRE deben diseñarse

Cualquier componente interactivo necesita todos estos estados:

```
Default     → Estado en reposo
Hover       → Mouse encima (desktop)
Focus       → Teclado/accesibilidad (outline visible obligatorio)
Active      → Click/tap en progreso
Disabled    → No disponible (reducir opacidad 40-50%)
Loading     → Procesando (skeleton ó spinner)
Error       → Validación fallida (borde rojo + mensaje)
Success     → Acción completada (✓ verde)
Empty       → Sin datos (ilustración + CTA guía)
```

## 🚫 Anti-patterns Clásicos de UX

| Anti-pattern | Problema | Solución |
|-------------|---------|----------|
| Dark pattern | Engaña al usuario | Diseñar con honestidad |
| Door slam | Registro forzado antes de valor | Onboarding → valor → registro |
| Confirmshaming | "No, no quiero ahorrar" | Opciones neutrales |
| Infinite scroll sin pausa | Adicción, pérdida de control | Paginación o "load more" con posición |
| Formulario interminable | Abandono | Progressive disclosure, multi-step |
| Error sin solución | Frustración | Mensajes con próximo paso |
| CTA poco claro | Confusión | Verbo + objeto: "Descargar guía" |
| Texto sobre imagen sin tratamiento | Ilegibilidad | Overlay semitransparente o blur |
| Sin estado vacío | Parece roto | Ilustración + mensaje + CTA |
| Notificaciones sin control | Irritación | Settings de notificaciones claros |
